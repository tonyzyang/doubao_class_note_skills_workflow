# 阶段三：撰写「课堂同步」内容（开场 + 逐页口述 + 问答）

把所有同步内容写进 `content.json`（可从 `assets/content_template.json` 复制）。

## 一、文字写什么：老师口述的知识点，不是翻译幻灯片（核心）

严禁把幻灯片上已有的标题、公式、要点复述/翻译一遍——图就在页面上，读者能直接看。

应写幻灯片上没有、老师口头展开的内容：

- 概念本质：一句话怎么理解；
- 为什么：为什么需要它、解决什么痛点、动机；
- 直觉与推导：公式为什么长这样、每步在干什么；
- 课上例子、老师的研究/工作经历、行业人物与故事；
- 易错点、易混点、与前后内容的承上启下。

判断标准：遮住图只看文字，读者能否学到老师讲到这页想传达的东西；文字若只是图的改写即不合格。

**两条硬判据（最高优先级，按此逐条验收）：**

1. **幻灯片上有、录音里没讲过的，一律不写。** 数字、参数、规格、清单明细、逐镜头台词都不例外——哪怕它们看起来很“完整”；数字只来自口述，约数保留“约”。唯一例外：幻灯片文字被老师在录音里亲口念出/复述，此时它属于口述内容。
2. **不照搬逐字稿原文。** 要把口述内容总结化、条理化（本质一句 + 分点 + 要点框），但知识点不得遗漏。
3. 写完每页必须回逐字稿检索该知识点，检索不到就删；用户曾因违反此点连续五次打回。

## 二、block 类型（写在每页 blocks 里）

- `{"type":"p","text":"段落"}`：正常讲解段；
- `{"type":"ul","items":[...]}`：松绿方点列表；
- `{"type":"note","text":"本页要点"}`：松绿要点框；
- `{"type":"ex","text":"课上举例"}`：金色举例框。

## 三、结构组织

按课堂真实顺序：

1. `opening`：开场/课程背景，可能对应标题页或无图，做成 2–4 张卡（课程定位、考核、改革全貌）。
2. `parts`：每部分逐页幻灯片，图在上、口述要点在下。
3. `qa`：现场问答，每问逐题收录题干与回答，不挑不删，独立成区（问朱砂、答松绿），不要并进某一页。
4. 有课间、第二部分同理。

## 四、查漏补缺（照片路径必做，PPT 路径一般不缺）

拿完整逐字稿与成稿逐段对照：老师明确讲过、本该有幻灯片却没拍到的，在正确位置插入**无图条目**（该 slide 不写 `image`，写 `tag`、`anchor`、`title`、`blocks`），渲染为虚线区块并标注“幻灯片没有拍到”；不要改动已有图的编号。老师的口头题外话就近配到最近的页。只补老师真正讲过的内容，不编造数字。

## 五、数字与口径

数字必须来自逐字稿，不目测、不凑整；口述约数保留“约”，复习区统一标注“多为口述约数，口径以正文为准”。
