# 阶段五：查漏补缺（交付前必做，防"漏"）

目标：在构建前，以**逐字稿为唯一主源**，确认录音里讲过的每个知识点、案例、数字都在 content.json 里有完整落点。这一步与"防伪"（PPT 有、录音没说的删）方向相反，专门防"录音说了、讲义漏了"。

## 为什么必须单独做

- 只做"防伪"不做"防漏"，最容易把**人物故事、行业经历、完整案例**当成花絮，只在复习区一句话带过，甚至完全不写（曾有近 3 分钟的完整口述案例因此漏掉）。
- 按 PPT 页核对会漏检：一张幻灯片可能对应十几分钟口述，按"页"而非按"话题"核对，页内的多个话题只落一个点。

## 步骤一：按话题逐段切分录音（不按 PPT 页）

1. 把逐字稿按**自然话题**切成小段，每段约 1–3 分钟、只讲一个话题（讲者话题切换处即切点，可用时间戳和说话内容判断）。
2. 每段记录：时间区间、话题、本质结论、案例/故事、人名、地名、机构、数字。
3. 形成一张"**段 → 落点**"对照清单，作为后续核对骨架。

## 步骤二：逐段配落点（正向核对：录音 → 讲义）

对每个小段，在 content.json 中找到它的落点（某 slide 的 blocks / 无图条目 / 复习区），并按下列判据验收：

- **超 1 分钟的独立案例、故事、人物经历，必须独立展开**（用 `ex` 或多个 `p` 块写出起因、经过、结果、点出的道理），**禁止只用一句话带过**，也禁止只在复习区出现。
- 每段的**数字、人名、地名、机构名**都要有落点；口述约数保留"约"。
- 一段对应多个知识点的，逐个落点，不能只落论点、不落论据。
- 与 PPT / 图片对不上的录音内容，按下列方式补，**不删录音内容**：
  - 该有幻灯片却没有 → 插入**无图条目**（不写 `image`，虚线块渲染）；
  - 有对应幻灯片但属于额外展开 → 正常写进该页 blocks；
  - 幻灯片顺序/主题与录音不一致 → 以录音为准，补讲内容跟随录音位置。

## 步骤三：独特关键词扫描

- 从逐字稿提取全部**独特词**：人名、地名、机构、事件名、专有概念、数字，逐个在 content.json 检索。
- 允许同义表述命中：如录音"假墙"、讲义写成"临街盖一面墙"，关键词不同但内容完整，算命中；检索时要同时搜索近义说法，避免误判。

## 步骤四：反向核对（防伪：讲义 → 录音）

- 逐条回逐字稿检索 content.json 里的每个知识点（尤其数字、参数、清单明细、台词），检索不到即删；幻灯片上有、录音没讲过的，一律不保留。此步与 05-validation 的反向核对要求一致。

## 步骤五：同步区 / 复习区交叉检查

- 课堂同步区是**完整展开**，复习区是**压缩索引**；二者是"详"与"纲"的关系。
- 任何知识点**不能只在复习区出现**而同步区缺失；现场问答必须同时在同步区 qa 与复习区 quiz 有落点。

## 交付前自查清单

- [ ] 录音已按话题逐段切分，段段有落点；
- [ ] 所有超 1 分钟的案例 / 故事 / 人物经历均已独立展开；
- [ ] 所有人名、地名、机构名、数字均有落点（约数保留"约"）；
- [ ] 与 PPT / 图片对不上的口述内容已补为无图条目或补讲块；
- [ ] 反向核对完成，无"PPT 有、录音没说"的内容残留；
- [ ] 无知识点只在复习区出现；现场问答两区均有落点。
